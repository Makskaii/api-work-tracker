# Пакеты техподдержки: работа аналитика

1. Откройте проект в разделе пакетов часов. «Добавить отчёт» позволяет выбрать задачу или оставить отчёт самостоятельным. Проект и компания заполняются из карточки проекта; задача должна относиться к этому же проекту.
2. Укажите выполненную работу, часы, дату и обязательный в Битриксе вид работы. «Учитывать в пакете» одновременно включает списание часов и отображение в клиентском отчёте. Создание и изменение выполняются с правами текущего пользователя Битрикса.
3. Часы автоматически распределяются по пакетам в порядке даты покупки и номера; отчёты — в порядке даты и номера. Дата покупки задаёт порядок пакетов, а не календарный фильтр отчётов. Остаток сверх последнего пакета отражается как перерасход. Пакет вручную в каждом отчёте выбирать не нужно.
4. Перед изменением часов/даты использованного пакета или его удалением проверьте показанные остатки до и после. Если другой пользователь успел изменить данные, расчёт нужно обновить. Изменение пакета и перераспределение списаний сохраняются одной транзакцией.
5. Перед выгрузкой посмотрите «Нужно проверить». Неуказанный лимит, превышение лимита незавершённой задачи и отсутствие описания — замечания. Задача другого проекта блокирует выгрузку до исправления связи. Часы автоматически не обрезаются, статус задачи из количества часов не выводится.
6. Обычный PDF строится заново по актуальным данным за весь выбранный пакет на сегодня. «Зафиксировать версию» сохраняет отдельный неизменяемый файл. Скачивание сохранённой версии не запускает новый расчёт. Старые версии сохраняются и после удаления пакета; искать их можно в истории проекта.

В PDF нет дат выполнения работ. У задачи «Сделано / Всего» означает фактические клиентские часы по задаче во всех пакетах / общий лимит. Работы других пакетов видны с пометкой и не добавляются к итогу выбранного пакета. Выключенный учёт в пакете исключает отчёт из клиентских списаний и PDF.

После закрытия карточки Битрикса или возвращения в окно данные сверяются заново. Кнопка «Обновить данные» запускает сверку вручную; время последнего успешного обновления позволяет отличить актуальные данные от ошибки связи. Если запись в Битриксе уже сохранена, ошибка последующей сверки не требует повторного создания отчёта.

## Обслуживание

- Перед выпуском применить миграцию `1791400000000-CreateSupportHoursReportVersions`.
- Сохранять в резервной копии и таблицу `support_hours_report_versions`, и каталог `uploads/support-report-versions` в постоянном томе. Метаданные без PDF-файлов недостаточны для восстановления.
- Сохранённые версии нельзя редактировать или удалять вместе с пакетом. Создание повторно с тем же UUID возвращает ту же версию.
- Предварительный расчёт возвращает отпечаток данных; подтверждение PATCH/DELETE передаёт его в заголовке `If-Match`. Устаревший отпечаток возвращает HTTP 409.
- Подготовка полей отчёта на сервере не изменяет Битрикс. Само сохранение выполняется через авторизованный SDK Битрикса в браузере, затем обновляется локальный учёт списаний.
